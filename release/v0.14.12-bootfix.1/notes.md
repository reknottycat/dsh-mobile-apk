# 0.14.12-bootfix.1

本次针对 `reknottycat/dsh-mobile-apk` 的启动恢复误判修复，选择性升级 Harness，并加入 Codex 自定义服务入口。包名仍为 `com.dsharnessmobile.shell`，versionCode 为 **71**。本版本沿用仓库既有签名；具体产物摘要与验证结果见同批交付的构建记录。

## 启动恢复修复

旧代码把 HTTP 401 当作等待就绪分支，一直等到 90 秒预算耗尽；与此同时，失败说明中的 `t_listen=-1` 是写死的文案，不是本轮的实际监听测量。不能仅用这句文案与分段日志的差异证明实际监听状态被覆盖。

现在把进程存活、HTTP 响应和认证状态分开记录。401 / 403 表示服务已经响应，会保留引擎并呈现对应认证状态；503 不视为可用。预算耗尽后增加两次间隔 5 秒的复探，破坏性恢复执行前再次检查。诊断保留脱敏 URL、状态码、耗时、动作原因和代次，不记录 token。

启动、停止、日志回调、看门狗和自动回退使用同一套生命周期代次约束。旧启动线程不能在新引擎启动后结束新进程；停止清理不在 UI 线程等待进程锁。自动回退在 CLI 列表查询之后及实际修改配置、恢复快照之前继续核验恢复资格。

## Codex 自定义服务

在 **设置 → 订阅 → ChatGPT（Codex）→ 自定义服务** 中填写平台的 API Base URL、API Key 和模型 ID，保存后从模型菜单选择 **Codex 自定义服务**。原有官方账号登录仍然可用。

地址填写平台提供的 API 基址，例如 `https://example.com/gateway/v1`，不要填写末尾带 `/responses` 的完整接口。平台需要支持 **OpenAI Responses API**；仅支持 `/chat/completions` 的平台不适用这条入口。模型 ID 使用平台提供的实际名称，不强制指定某个官方模型。

自定义服务通过独立 `codex-custom` provider 与普通 API Key 发送请求。它不会读取或改写官方 OAuth 记录，也不会把官方账号令牌发送到自定义地址。API Key 存入 Harness 私有凭据服务，设置文件只保存独立引用；修改地址时要求重新填写该地址的密钥。保存后密钥输入框清空，不从服务端回显。

保存使用配置修订号防止覆盖并发修改。界面只确认配置已保存，不把它描述成平台连通测试；实际发起对话后才能确认所填平台、密钥与模型组合可用。本次回归用真实 Harness 适配器和本地 HTTP/SSE 服务，验证保留基址路径、流式响应和密钥轮换。

## 用户配置与撤销诊断

升级保留 `settings.yaml.imported` 标记。已迁移安装使用 `profiles/web/cordis.patch.yml`，不会再次播种工厂旧设置；未迁移且仍有旧设置的安装继续选用原文件。PTC 的旧 `nodeExecutable` 仅在适用条件下转换为新 `launch` 格式，并保留用户路径与其他配置。

导出、导入和备份统一选择实际活动文档。导入先验证，再完整备份，最后原子替换。完整导出含执行型 YAML 时，界面会明确提示它是备份，不能从共享目录原样导入。导入完成显示实际备份路径。

`undo_doctor` 同时接受字符串、字符串数组和合法空数组形式的 bundle patch，并把真实引擎入口加入模块解析锚点；仍会拒绝损坏声明和实际缺失文件。

## 退出观察的含义

`files/engine-exit.log` 记录插件加载后的 `boot`、真实 `exit` code 和 `uncaughtExceptionMonitor`，带有体积上限与轮转。探针不新增 SIGTERM / SIGINT 处理器，保持原有进程退出语义。

只有 `boot` 而没有退出行，可能是默认 SIGTERM / SIGINT、SIGKILL、原生终止或日志尚未落盘，不能独立判定原因。应与壳侧动作日志、PID 和代次一起判断。此前用户提供的日志节选没有在这台构建环境中重新采集，不能据此排除所有系统回收或原生崩溃。

## 安装与验证

手机使用 **arm64 APK**；x86_64 APK 用于对应架构的模拟器。相同包名和签名时可覆盖安装。首次打开需要刷新内嵌运行时，应保持应用在前台，等刷新完成再测试手动重启。

自动化测试、产物签名与设备检查的最终结果随构建记录提供。没有在用户实际手机上完成验证的项目，不作为已验收项目宣称。
